# 百炼模型成本与延迟优化需求

## 背景

本需求提出时，Restaurant Search Agent 默认使用 `deepseek-v4-flash-0731`。百炼自
2026-08-17 起调整该版本价格后，持续使用同一模型承担目标理解、关键词扩展、候选验证和
搜索重规划，已经不能满足当前成本约束；一次完整餐厅推荐约 25 秒，也不能满足高频使用时
的响应体验。

本需求只优化当前确定性 workflow 中的一次性结构化模型角色，不把这些角色改造成 Agent，
也不改变餐厅搜索、证据准入、授权或最终推荐规则。

## 用户与运营需求

1. 用户在不牺牲推荐正确性和约束遵守的前提下，更快看到第一批搜索进展和最终推荐。
2. 高频调用的候选验证和关键词扩展使用成本更低的模型，避免少量复杂角色决定整轮成本。
3. 模型迁移不能让思考内容、普通文本或不完整 JSON 进入强制结构化输出链路。
4. 运维可以只通过环境变量覆盖任一角色模型，并能从 trace 或日志确认实际生效的模型、
   延迟、Token 和重试情况。
5. 新模型出现质量或可用性回归时，可以通过配置回滚，不依赖紧急改代码。

## 已接受的产品决策

- 默认模型组合使用百炼华北 2（北京）可用的稳定模型别名：
  - 目标理解、搜索重规划：`qwen3.7-flash`；
  - 关键词扩展、候选验证：`qwen-flash`。
- 强制工具调用场景固定使用非思考模式。模型不允许通过部署配置开启思考模式后破坏
  `tool_choice` 契约。
- `OPENAI_MODEL_<ROLE>` 继续作为单角色覆盖，`OPENAI_MODEL` 继续作为全角色覆盖，避免
  现有部署 secret 失效；没有显式覆盖时才使用新的角色默认值。
- 首期不在一次用户请求内自动切换备用模型。自动回退会延长失败请求、增加重复账单，并
  可能让同一轮出现不同语义判断。回滚采用部署配置切换。
- 价格和官方模型定位用于筛选候选，是否真正改善 25 秒端到端延迟必须由同一批真实请求的
  对照数据证明，不能用厂商的 Flash 命名代替实测。

## 验收标准

### 配置与兼容性

- 未设置任何模型名称变量时，各角色解析为已接受的默认模型组合。
- `OPENAI_MODEL` 能覆盖全部角色；单角色变量能继续覆盖 `OPENAI_MODEL`，且空白值不算有效
  配置。
- 默认 Base URL 指向百炼 OpenAI 兼容接口；生产可以配置业务空间专属域名，已有
  `OPENAI_BASE_URL` 和 `OPENAI_API_KEY` 名称保持兼容。
- Qwen 或百炼兼容端点上的强制工具调用请求始终发送 `enable_thinking=false`。
- 迁移后仍使用现有 schema 校验、截断修复、有限重试和类型化错误，不增加静默本地语义
  降级。

### 可观测与对照

- turn 级指标同时报告模型调用次数、模型调用累计耗时、模型实际占用的墙钟时间、Token、
  重试、失败，以及按模型角色和实际模型 ID 的聚合。
- 使用不少于 30 条覆盖 typical、edge、adversarial 的固定语义用例；延迟对照至少收集
  100 个成功 turn，结构化输出失败率对照至少收集 200 次模型角色调用。迁移前后必须使用
  同地域、同搜索 fixture 或同等 Provider 条件。
- 对照至少报告：端到端 P50/P95、首次搜索结果时间、模型墙钟 P50/P95、每轮输入/输出
  Token、schema 修复率、失败率和推荐结果回归。

### 发布门槛

- `npm test`、`npm run type-check`、`npm run lint` 和 `npm run eval` 通过。
- 新组合不得引入硬约束、授权、证据分区或最终推荐发布回归。
- 正式切流前的真实百炼 A/B 中，端到端 P50 和 P95 均不得劣于当前模型；模型成本必须按
  各模型响应返回的实际输入/输出 Token、对应输入档位和官方原价估算，并降低至少 50%。
- 若结构化输出失败率上升超过 1 个百分点，或关键 Agent eval 出现任何硬约束/授权回归，
  不得正式切流。

## 非目标

- 本次不承诺单靠更换模型把所有请求稳定压到某个固定秒数。
- 本次不重写 Agent workflow、搜索并发、Amap 详情抓取或前端进度协议。
- 本次不实现自动跨模型重试、上下文缓存、Batch API 或新的模型网关。
- 本次不把百炼当前活动折扣写成长期成本承诺。
