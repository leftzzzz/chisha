# 公网运行保护与供应商容量管理

## 背景

ChiSha 公开上线后，所有访客共享部署者的高德与阿里云模型凭证。一次 Agent 请求会并行
执行多个搜索计划、候选详情补全和模型验证；单纯按 HTTP 请求数限流既不能准确保护上游
配额，也不能在 Cloudflare 多隔离实例之间形成全局上限。

本需求不降低 Agent 的搜索质量来换取表面稳定性。`AGENT_SEARCH_CONCURRENCY` 继续表示
一轮允许并行探索的搜索计划数，供应商容量由独立的全局调度层控制。

## 2026-08-18 外部配额核验

- 高德[流量限制说明](https://lbs.amap.com/api/webservice/guide/tools/flowlevel)要求在控制台
  “流量分析-配额管理”查看当前服务的精确配额；公开资料没有“免费版恒为 1 QPS”的规则。
  [产品定价页](https://lbs.amap.com/upgrade#price)区分不同认证与授权对应的搜索月调用量，
  并说明搜索服务配额在相关端之间共享。因此月调用量、QPS 和单次 Agent fanout 是三个
  不同维度，不能互相替代。
- 阿里云百炼[限流说明](https://help.aliyun.com/zh/model-studio/rate-limit)表明，限流按阿里云
  主账号汇总其 RAM 用户、业务空间和 API Key，并按具体模型分别计算 RPM/TPM；短时间
  RPS/TPS 突增也可能被拒绝。免费额度耗尽与请求速率超限是不同错误，充值或续费不会自动
  提高 RPM/TPM。
- 仓库和部署 secret 名称不能证明控制台的实时数值。上线时必须记录高德控制台最小 QPS、
  当前实际模型及该模型 RPM/TPM；尚未取得数值的维度采用严格在途上限和保守安全值，不能
  在文档中冒充已确认配额。

## 用户与运营目标

1. 正常访客在容量允许时可以继续使用并行搜索，不因高德免费版被固定为 1 QPS。
2. 突发访问不会把高德、阿里云模型或 OSM 同时打穿，也不会无限占用部署者预算。
3. 短暂拥塞允许等待；等待超过交互式请求可接受窗口后，快速返回可重试错误，不无限排队。
4. 高德额度耗尽时明确降级或报错；补充流量包并恢复额度后，服务可自动恢复。
5. 匿名用户只能读取、继续和删除自己浏览器创建的 Agent 会话。
6. 运营者可以从结构化日志判断拒绝发生在入口、会话、供应商队列还是上游配额。

## 已接受的产品决策

### 并发与排队

- 保留 Agent 逻辑 fanout，默认 `AGENT_SEARCH_CONCURRENCY=3`。
- 高德 QPS 不固定为 1。生产值由高德控制台实际的账号、服务和 Key 限制中的最小值决定，
  初始安全值为 `floor(minQps * 0.7)`；上线前必须记录采用的值。
- 对一次上游调用只允许 2 至 5 秒的短等待。超过等待窗口返回 `429` 或 `503` 及
  `Retry-After`，不得把同步 SSE 请求留在无界队列中。
- 不在本期引入 Cloudflare Queues。只有产品改为异步任务并接受 `jobId`、后台执行和结果
  轮询时，才使用持久队列。

### 公网准入

- 所有公网 HTTP 请求必须在进入应用和会话逻辑前升级到 HTTPS。重定向必须保留 POST 方法、
  请求体、路径和查询参数，不能让依赖 `Secure` Cookie 的追问续跑在 HTTP 页面中失去匿名
  owner；本地回环地址继续允许 HTTP 开发。
- `/api/agent/chat` 同时受单客户端频率、全站运行数和同一会话互斥保护。
- `/api/search` 不能绕过公开入口保护，且关键词数量、单词长度、半径和结果数必须有上限。
- IP 只用于反滥用提示，不作为身份或唯一账单保护。Cloudflare 环境优先使用可信的
  `CF-Connecting-IP`，不得优先信任客户端可伪造的转发头。
- 核心全局协调绑定在生产缺失时应拒绝昂贵请求并暴露配置错误，不能静默退化成单实例
  内存限流。

### 匿名会话

- 首次创建会话时，为浏览器签发 HttpOnly、Secure、SameSite=Lax 的签名匿名所有者 Cookie；
  token 自身必须包含服务端校验的到期时间，不能只依赖浏览器 `Max-Age`。
- 所有者必须在 SSE 响应建立前完成校验或签发，不能依赖流开始后修改响应头。
- Agent 会话持久化所有者标识；继续、读取 trace 和删除都必须匹配该所有者。
- 对不存在和不属于当前所有者的会话统一返回未找到，避免枚举会话 id。
- 同一会话同时只允许一个运行，防止整行状态持久化产生最后写入覆盖。

### 上游故障

- 高德 QPS 限制、日配额耗尽、Key/签名错误和普通服务故障必须分类处理。
- 只有可恢复的 QPS/瞬时服务错误可以按有界策略重试；日配额耗尽和配置错误不得重试放大。
- 高德不可用时可以尝试受独立容量保护的 OSM，但降级不能绕过用户范围、证据和
  FinalGuard。
- 配额耗尽和配置错误应短路后续请求并定期探测恢复，避免每个访客都重复撞击已知故障；
  补充流量包后不需要重新部署即可恢复。
- 阿里云模型按端点与模型维度限制全局在途数，并允许按控制台数据配置 RPM/TPM。
- 高德月量耗尽后允许运营者补充流量包；恢复探测成功后必须自动解除熔断，无需重新部署。

## 验收标准

1. 三个并行搜索计划仍可同时进入 Runtime，但所有 Worker 实例的高德调用起始速率不超过
   `AMAP_SAFE_QPS`，且详情补全有单次运行内并发上限。
2. 同时到达的 Agent 请求超过全局运行上限时，先短等待，随后得到带 `Retry-After` 的
   可重试响应；队列不会无界增长。
3. 模型调用具有跨实例的在途上限；配置 RPM/TPM 后，调度器在发送请求前预留预算。
4. 高德配额耗尽错误不重试；瞬时限速遵守退避；OSM 降级也经过独立保护。
5. 伪造 `X-Forwarded-For` 不能覆盖 Cloudflare 提供的真实客户端 IP。
6. 未持有正确所有者 Cookie 时，无法读取、继续或删除已知 session id。
7. 同一 session id 的两个并发请求最多一个进入 Agent 执行。
8. 生产缺失调度绑定或所有者签名密钥时，昂贵入口失败关闭并记录配置错误。
9. session 查询和删除有独立的廉价入口限流，随机枚举不能形成无界 D1 读取。
10. 单测覆盖调度授予、超时、租约续期/过期、配额分类、会话归属和入口拒绝；Agent 行为改动运行
   `npm run eval`，部署前通过类型检查、lint、构建与 Cloudflare dry-run。
11. 线上验收至少包含健康页面、正常 Agent SSE、同会话互斥、匿名越权拒绝和日志无新增
    5xx；不以主动耗尽真实供应商额度作为验收手段。
12. 发布记录明确区分“代码默认安全值”和“控制台已核验值”；未获控制台证据时不得声称
    已确认账号级高德 QPS 或阿里云模型 RPM/TPM。
13. `http://` 公网入口在应用处理前重定向到同路径 `https://`；POST/SSE 建连请求使用保留
    方法和请求体的状态码，手机浏览器从 HTTP 入口进入后仍能继续自己的追问会话。

## 非目标

- 本期不实现登录、付费套餐或按用户计费。
- 本期不改造为异步搜索任务，不承诺拥塞请求最终一定执行。
- 本期不改变 Restaurant Search Agent 的语义决策、搜索范围、证据模型和 FinalGuard。
- 本期不猜测高德或阿里云控制台配额；无法从代码确认的数值必须由部署配置给出。
