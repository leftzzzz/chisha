# Application Behavior Spec

本 Spec 适用于 `app/` 页面、`components/`、`context/`、`hooks/`、`lib/storage.ts`、
`lib/share.ts`、`lib/turntableOptions.ts` 及其测试。产品意图见
[ChiSha 业务规则与产品边界](../requirements/chisha-product-rules.md)，实现结构和取舍见
[应用架构](../technical/application-architecture.md)。Agent 的候选准入仍由
[Restaurant Search Agent Spec](./restaurant-search-agent.md) 负责。

## 状态与入口

- 应用状态以 `AppContext` 和 `AppReducer` 为单一客户端状态源。正常流程是
  `INPUT -> UNDERSTANDING/SEARCHING -> READY -> SPINNING -> RESULT`；Agent 需要补充信息时
  进入 `AGENT_QUESTION`，失败进入 `ERROR`。
- 新搜索必须同时具备非空自然语言输入和有效位置。位置来自浏览器定位或地址地理编码；
  分享内容中的占位位置不能用于新搜索。
- 开始新搜索时必须取消上一条仍在运行的请求，清除旧追问，并为新会话重置 trace；续跑
  追问时保留同一个 `sessionId`。
- 点击追问选项只回传稳定 `optionId`；自由文本才作为 `message` 交给目标理解模型。前端
  不得根据展示文案推断选项效果。

## 推荐结果发布到界面

- 后端的 `restaurants` 是主推荐，`candidates` 是候补。Reducer 必须保留分区，候补不得
  自动进入转盘。
- 主推荐只做固定展示上限裁剪和同一物理地点去重；不得用候补补足、按品牌折叠不同门店、
  重排后端选择，或把超出展示上限的主推荐改标为候补。
- 餐厅去重使用 `getRestaurantIdentityKeys` 的地点身份键。主推荐、候补、搜索新增和恢复
  路径必须避免同一地点重复出现。
- Agent 的整体说明、未满足约束和候补警告必须与结果一起保留；界面不得自行生成更强的
  满足性结论。
- 候补只有在用户执行“加入转盘”后才能转入主转盘，且仍受容量和地点去重约束。

## 转盘

- `MIN_TURNTABLE_OPTIONS=3`、`MAX_TURNTABLE_OPTIONS=8` 是数量契约的代码真源；餐厅与
  自定义文字选项共享上限。
- 少于 3 个选项时不得开始转动。删除、移入候补或删除自定义选项导致不足 3 个时，状态
  回到输入态并显示真实原因。
- 用户可以移除餐厅、恢复已移除餐厅、在转盘与候补之间移动餐厅、搜索并添加餐厅，或
  添加自定义文字选项。任何添加路径都不得超过 8 个选项。
- `selectedIndex` 必须在餐厅与自定义选项合并后的稳定顺序中解释；删除位于选中项之前的
  选项时同步调整索引，删除选中项时重置索引。
- 转动完成后只发布实际选中的选项。再次转动复用当前选项集合，不重新搜索或改变候选
  证据状态。

## 历史、偏好与分享

- 从 `SPINNING` 首次进入 `RESULT` 时保存一条本地历史，记录查询、位置、参与选项、手动
  移除餐厅和选中结果；同一次状态变化不得重复保存。
- 历史存储在浏览器 `localStorage` 的 `chisha_history`，按时间倒序读取，最多 100 条。
  同一查询、相同坐标且 30 分钟内的再次转动替换旧记录，只保留最后结果。
- 历史导入必须校验数据结构；合并、删除、清空、搜索和导出都只操作本地历史。存储不可用
  或写入失败时必须显式失败或记录错误，不得声称已持久化。
- 从历史恢复时只恢复查询、位置和不超过 8 个的选项；不得恢复旧 Agent 会话、trace、
  候补或证据状态。恢复后仍至少需要 3 个选项。
- 历史中的随机选中结果只用于展示和“抽中次数”统计，不得直接形成餐厅、菜系、距离或价格
  强偏好。相同候选集合只改变随机选中项时，偏好摘要必须保持不变。
- 参与转盘的候选可以提供弱曝光信号；只有显式 `like` 反馈才形成强正向信号，显式
  `dislike` 或手动移除才形成负向信号。历史生成的偏好摘要不得覆盖本次明确位置、硬约束
  或排除项。
- 分享链接只携带压缩后的查询、餐厅和自定义选项，不携带位置、Cookie、Agent 会话或
  trace。加载分享内容只恢复转盘；开始新搜索前必须重新选择有效位置。

## 错误与验证

- 可重试性以错误码配置为单一来源；配额耗尽或配置缺失等确定失败不得显示无效重试入口。
- Reducer 的无效索引操作保持原状态，不得产生部分更新。
- 变更这些行为时至少运行对应 Reducer、hook、storage 或组件测试；跨 Agent 发布边界的
  变更还必须运行 `npm run eval`。
