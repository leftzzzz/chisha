# 通用工程任务规则

## 适用边界

- 本规则适用于代码、配置、脚本的新增、修改、修复和审查。
- 专项规则仅在根 `AGENTS.md` 索引明确触发时适用。
- 用户要求分析、解释或审查时，只做只读检查；除非用户同时明确要求修改。
- 用户要求实现或修复时，完成必要修改和验证，不停留在方案描述。

## 决策优先级

本规则内部发生冲突时，依次优先：

1. 用户明确要求和验收条件；
2. 正确性、安全性、数据完整性和既有外部契约；
3. 仓库中已经生效的架构与约定；
4. 完成任务所需的最小改动范围；
5. 局部可读性和代码风格。

不得为了满足较低优先级而破坏较高优先级。

## 执行规则

- **先读后改**：修改前读取目标实现、最近调用方、相关测试和适用规则；不得仅凭文件名、局部片段或惯例推断行为。
- **保持最小但完整**：只修改完成目标所必需的代码、直接依赖和测试；保留用户已有改动，不混入无关重构。需要改变额外行为或架构时，先取得用户确认。
- **优先现有责任点**：现有代码能够保持正确性和主流程可读时，直接扩展它。只有出现独立不变量、独立生命周期、真实多处复用、可替换实现或独立失败边界时，才新增抽象。
- **拒绝推测性设计**：不得仅以“以后可能需要”为由增加兼容、兜底、缓存、锁、重试或补偿。存在实际输入、调用入口或故障证据时，将处理集中在一个明确边界，并写清触发条件。
- **先确认数据契约**：在不可信输入边界完成校验和归一化；内部代码使用已经确认的契约。契约不清楚时追踪数据来源和调用方，不得用静默默认值掩盖问题。
- **保持主流程可读**：主流程按实际执行顺序组织。只为稳定业务阶段、真实复用或独立失败边界提取方法；仅转发参数或包装一次调用的方法默认内联。
- **保留状态差异**：不得混淆合法零值、空结果、缺失数据、无效输入、确定失败和结果未知。涉及外部副作用时，明确失败影响及是否重试。
- **只写有决策价值的注释**：注释说明非直观的不变量、业务原因、失败后果或安全路径；不逐行复述代码，不使用无法对应实际行为的抽象表述。

## 单一真源

- 同一业务定义、计算公式、状态语义、字段映射、默认值或格式化策略，只保留一个可独立修改的权威来源；其他位置必须引用、调用或由该来源生成。
- 缓存、快照、索引、反范式数据和兼容输出可以保留副本，但必须明确权威来源、生成入口以及失效或重建方式；不得形成两个都可独立写入的来源。
- 修改前先定位权威来源；发现多个实现或规则冲突时，先收敛或报告冲突，不得在新位置继续复制。

## 验证与交付

- 使用仓库已有命令运行与改动最接近的测试和静态检查；共享行为或跨模块契约发生变化时扩大验证范围。
- 行为修复应优先补充能够复现问题的回归测试；不适合增加测试时说明原因和采用的替代验证。
- 交付前检查完整 diff，确认请求行为已实现、既有契约未被意外改变且没有无关改动。
- 只报告实际执行的验证及其结果；未执行、失败或受环境限制的检查必须明确说明。
