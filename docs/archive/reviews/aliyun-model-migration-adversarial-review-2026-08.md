# 百炼模型迁移文档对抗性审查（2026-08）

## 审查范围

- `docs/requirements/aliyun-model-cost-latency.md`
- `docs/technical/aliyun-model-routing-2026-08.md`
- `docs/specs/model-provider-routing.md`

审查从成本失真、延迟误判、配置未生效、模型漂移、工具调用不兼容和质量回归六类失败场景
反推文档是否可实施。本文记录审查结果，不替代 requirement、technical 或 Spec。

## 发现与处理

### 已修正：样本量不能支持失败率门槛

第一版同时要求“不少于 30 条查询”和判断结构化失败率是否上升 1 个百分点。30 条样本最多
只能以约 3.3 个百分点为步长观察整轮失败，更不能覆盖一轮中的多个模型角色。

处理：拆分语义用例、延迟 turn 和模型角色调用三种样本。语义覆盖不少于 30 条，延迟不少于
100 个成功 turn，结构化失败率不少于 200 次角色调用。1 个百分点仍是风险门槛，不把小样本
无显著差异误写成“证明等价”。

### 已修正：稳定别名提高容量但降低复现实验能力

稳定别名有更好的官方限额和维护路径，但平台可以把它指向新快照。如果指标只保存请求别名，
一次回归无法确定是否发生了模型升级。

处理：逐调用指标同时保留请求 `model` 和供应商返回的 `responseModel`，聚合优先使用后者；
供应商只返回别名时明确记录实验时间，不虚构具体快照。

### 已修正：合并代码不等于生产完成分流

配置优先级保留了兼容性，但生产现有 `OPENAI_MODEL=deepseek-v4-flash-0731` 会覆盖所有新默认
值。若发布清单不处理该变量，代码上线后成本和延迟不会变化。

处理：技术发布步骤增加生产变量盘点；先用全局变量灰度 `qwen3.7-flash`，再用 keyword 和
evaluation 角色变量启用 `qwen-flash`。文档禁止把代码默认值变更宣称为线上切流完成。

### 已修正：不同模型 Token 数不能按“相同 Token”估价

不同模型可能对同一输入返回不同 usage，输出长度也可能不同。直接拿同一 Token 数乘价格会
低估结构化冗余或重试成本。

处理：成本门槛改为使用各模型实际 usage、对应输入阶梯和官方原价计算；所有 schema 修复和
截断重试都必须计入。

### 已接受风险：Flash 名称不证明本项目更快

官方只给出模型定位和通用响应速度影响因素，没有本项目 prompt 的横向 P95。模型更便宜是
可由价格表确认的事实，更快只是待验证假设。

处理：不设置未经数据支持的固定秒数承诺；要求端到端 P50/P95 均不劣化，并同时观察模型
墙钟时间和首次搜索结果时间，以区分模型、Amap 和 workflow 的贡献。

### 已接受风险：不做请求内自动回退

不自动回退意味着模型故障时用户会看到显式失败；自动回退则会增加 P95、重复账单和同轮
语义不一致。本次目标是降低成本和延迟，后者与目标直接冲突。

处理：保留现有类型化失败，用环境变量做部署回滚。若未来业务要求高可用模型回退，必须另立
需求并定义总 deadline、可回退错误、幂等、账单和一致性边界。

## 审查结论

修正后文档可以作为当前确定性 workflow 的实现依据。实现不得扩大为 Agent 重构、自动模型
路由或线上 secret 修改；真实百炼 endpoint 的质量和延迟验收仍是正式切流前置条件，而不是
本地桩模型测试可以替代的事项。
