# 百炼模型迁移实现对抗性审查（2026-08）

## 审查范围

- `lib/agent/modelConfig.ts`
- 四个结构化模型角色调用入口
- `lib/agent/modelClient.ts`
- `lib/agent/metrics.ts`
- 相关单测、Runtime trace 和环境文档

审查从“配置没有真正生效、百炼请求被拒绝、成本指标失真、回滚失效和业务边界被放宽”
反推实现，而不是只检查默认路径能否编译。

## 发现与处理

### 已修正：业务空间地址漏识别

百炼专属业务空间使用 `*.maas.aliyuncs.com`。首版只按 `dashscope`、`qwen` 或模型名
识别百炼请求，专属空间调用 DeepSeek 等非 Qwen 模型时会漏发
`enable_thinking=false`，而强制 `tool_choice` 与思考模式不兼容。

处理：传输层识别 DashScope 通用域名、百炼业务空间域名和 Qwen 模型名，并为业务空间地址
增加回归测试。非百炼 OpenAI-compatible 地址仍不附加供应商参数。

### 已修正：失败调用的尝试次数漏计

首版在收到 HTTP 响应后才累计 `attempts`。网络异常、限流或调度租约失败时，trace 可能把
已发起的请求记成零次，导致重试率和成本估算偏低。

处理：每次真正取得模型调度租约、即将发起 HTTP 请求前记录一次尝试；tools 到 functions
的协议重试、截断重试和 schema 修复重试都进入同一个计数。仅在尚未取得租约、没有发出请求
时不计数。

### 已修正：稳定别名掩盖实际模型版本

只记录请求别名无法识别百炼稳定别名在实验期间是否指向了新版本。

处理：解析响应顶层的 `model` 字段为 `responseModel`，保留请求 `model`；turn 聚合优先按
`responseModel ?? model` 分组。供应商不返回、返回空字符串或返回非字符串时不虚构版本号。

### 已修正：上下文建立前的失败调用不可观测

Supervisor 需要先解析目标才能创建 RuntimeState。首版在这个边界失败时虽然保持了“不写半成品
状态”，但已经发出的模型调用指标也随错误一起丢失，无法核对失败率和实际尝试次数。

处理：在 `runSearchAgentV3` 外层保留目标解析阶段的指标；若尚未建立 RuntimeState 就失败，
将不含 prompt/API Key 的汇总写入带 session 上下文的错误日志。进入 RuntimeState 后仍按原契约
写入 `model_call` trace 和完成日志。

### 已确认：配置回滚边界

解析入口在每次模型调用时读取环境变量，因此同一 Worker 不会因模块加载时机继续使用旧配置。
优先级仍为角色变量、全局变量、角色默认值；生产若保留旧的 `OPENAI_MODEL`，它会有意覆盖
新角色默认值。

处理：需求、技术方案和发布清单明确要求盘点并清理生产变量；回滚通过环境变量完成，不在请求
内静默切换模型。

### 已确认：业务安全边界未放宽

迁移只替换结构化模型配置和传输参数，保留 schema 校验、截断/schema 修复、类型化错误、
候选验证 guard、授权和 FinalGuard。未新增本地语义替代、证据生成或自动跨模型回退。

## 尚未在本地证明的风险

- 没有生产百炼 API 凭据和同地域线上样本，本地桩模型 eval 不能证明真实 P50/P95、首搜时间、
  结构化失败率或成本降低 50%。这些仍是正式切流前置门槛。
- 稳定模型别名可能在未来升级；正式 A/B 必须保存测试时间和供应商 `responseModel`（若返回）。
- 生产业务空间的 RPM/TPM、活动折扣和实际 Token 价格必须以百炼控制台为准，不能由仓库默认值
  推断。

## 审查结论

修正后实现满足当前 Spec 的配置、工具调用和指标契约，可以合入并进入真实百炼 A/B；本次
代码合并不等于生产切流完成。
