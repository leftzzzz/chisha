## 二、核心模块设计

### 2.1 页面状态机

应用采用单页面多状态设计，通过状态机控制页面流转：

```typescript
type AppStep =
  | 'INPUT'         // 输入态：用户输入需求和位置
  | 'UNDERSTANDING' // 理解态：LLM 分析中
  | 'SEARCHING'     // 搜索态：调用地图 API
  | 'READY'         // 就绪态：转盘已生成，等待用户操作
  | 'SPINNING'      // 转动态：转盘旋转中
  | 'RESULT'        // 结果态：展示推荐餐厅
  | 'ERROR';        // 错误态：显示错误信息

// 状态转移规则
const transitions = {
  INPUT: ['UNDERSTANDING'],
  UNDERSTANDING: ['SEARCHING', 'ERROR'],
  SEARCHING: ['READY', 'ERROR'],
  READY: ['SPINNING', 'INPUT'],
  SPINNING: ['RESULT'],
  RESULT: ['SPINNING', 'READY', 'INPUT'],
  ERROR: ['INPUT'],
};
```

## 三、响应式设计策略

### 3.1 断点定义

| 断点名称 | 宽度范围 | 设备类型 |
|---------|---------|---------|
| mobile | < 768px | 手机 |
| tablet | 768px - 1024px | 平板 |
| desktop | > 1024px | 桌面 |

### 3.2 布局策略

**PC 端 (desktop)**
- 全屏地图背景
- 左侧玻璃面板（转盘 + 候选列表）
- 结果以悬浮卡片形式显示在地图上

**移动端 (mobile)**
- 转盘居中显示
- 地图作为背景（弱化）
- 结果以底部浮层形式显示

```tsx
// 实现方式：条件渲染
const MainPage = () => {
  const isMobile = useMediaQuery('(max-width: 768px)');

  return isMobile ? <MobileLayout /> : <DesktopLayout />;
};
```

## 四、性能优化策略

### 4.1 加载优化

| 优化项 | 策略 |
|-------|------|
| 首屏加载 | SSR 渲染首页静态内容 |
| 地图库 | 动态导入，首屏不加载 |
| 历史页 | 延迟加载 (lazy) |
| 字体 | 使用系统字体栈 (-apple-system) |

### 4.2 运行时优化

| 优化项 | 策略 |
|-------|------|
| 转盘动画 | CSS Animation，GPU 加速 |
| 状态更新 | useReducer 批量更新 |
| 地图渲染 | 仅在需要时初始化 |
| 图片 | 使用 next/image 自动优化 |

### 4.3 API 调用优化

```
原始流程（串行）：
LLM理解(8s) → 地图搜索(10s) = 18s

优化流程（部分并行）：
LLM理解(8s) ──────────────┐
                          ├─▶ 合并结果 → 完成
默认搜索(10s，投机执行) ───┘

实际等待：max(8, 10) = 10s（节省 8s）
```

## 五、安全设计

### 5.1 API 密钥保护

```
客户端 ──X──▶ 第三方API（禁止直接访问）
    │
    └──────▶ Next.js API Routes ────▶ 第三方API
              (密钥存储在服务端)
```

### 5.3 输入验证

| API 请求 | 请求体 schema 验证 |

## 六、错误处理策略

### 6.1 错误分类

| 错误类型 | 处理策略 | 用户提示 |
|---------|---------|---------|
| LLM 超时 | 使用原始输入搜索 | "AI 理解超时，使用原始输入搜索" |
| LLM 解析失败 | 使用原始输入搜索 | 同上 |
| 地图无结果 | 显示空状态 | "未找到符合条件的餐厅，请修改需求" |
| 地图超时 | 允许重试 | "网络超时，点击重试" |
| 定位失败 | 切换手动输入 | "无法获取位置，请手动输入" |
| 网络断开 | 阻止操作 | "网络已断开，请检查连接" |

### 6.2 降级策略

```
LLM 服务不可用
    │
    ├─▶ 使用用户原始输入作为关键词
    │
    └─▶ 直接调用地图 API 搜索

高德地图不可用
    │
    └─▶ 降级到 OSM Overpass API（备选）
```

## 七、可扩展性设计

### 7.1 第二期功能预留

| 功能 | 架构预留 |
|-----|---------|
| 用户账户 | Context 中预留 user 字段 |
| 云端历史 | storage.ts 抽象接口，后期切换实现 |
| 更多地图源 | 地图服务抽象为 adapter 模式 |
| 分享功能 | 结果状态可序列化为 URL 参数 |

### 7.2 接口抽象示例

```typescript

interface IStorageAdapter {

class LocalStorageAdapter implements IStorageAdapter { ... }

// 第二期：云端 API 实现
```
