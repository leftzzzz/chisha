# 产品需求文档（PRD）

## 项目名称
**今天吃啥** - 智能餐饮推荐转盘

## 一、产品概述

### 1.1 产品定位
一款智能餐饮推荐工具，通过自然语言理解用户需求，调用AI和地图API获取符合条件的餐厅，并通过幸运转盘形式让用户随机选择，解决"不知道吃什么"的决策问题。

### 1.2 目标用户
全年龄段，主要场景：
- 工作日午餐/晚餐时不知道吃什么
- 外出游玩时寻找当地餐厅
- 想要尝试新餐厅但没有明确目标的用户

### 1.3 核心价值
- **降低决策成本**：用户仅需一句话表达需求，无需填复杂表单
- **公平随机性**：转盘形式增加趣味性，避免用户纠结
- **个性化推荐**：基于AI理解的需求进行精准推荐

## 二、功能需求

### 2.1 核心流程

```
用户输入需求 → LLM理解并转化为搜索条件 → 调用地图API获取餐厅
→ 填充转盘（8家） → 用户点击转动 → 获得推荐结果
→ 查看详情/保存/再来一次
```

### 2.2 功能模块详解

#### 2.2.1 需求输入页面
**功能描述**：用户通过自然语言输入餐饮需求

**输入方式**：
- 文本输入框（单行或多行）
- 示例文案提示用户：
  - "我想吃点清淡的"
  - "想吃川菜，人多的地方"
  - "最近想尝试新的日料店"
  - "附近有什么快餐吗"

**位置获取**（两种方式，用户可选）：
1. **自动定位**：使用浏览器Geolocation API获取用户当前坐标
   - 首次使用时弹出权限请求
   - 失败时降级到手动输入
2. **手动输入**：用户输入地址或地名
   - 支持搜索补全
   - 示例："北京朝阳区"、"上海浦东新区南京东路"

**输入验证**：
- 需求不能为空，至少1个字
- 位置信息不能为空
- 按钮状态：有效输入时才激活"获取推荐"按钮

---

#### 2.2.2 LLM需求理解模块
**功能描述**：将用户的自然语言需求转化为结构化的搜索参数

**处理流程**：
```
用户输入："最近想吃点清淡的素食" + 位置信息
↓
调用OpenAI API (GPT-4或GPT-3.5)
↓
返回结构化结果：
{
  "keywords": ["素食", "清淡"],
  "cuisineTypes": ["素菜馆", "蔬菜"],
  "priceRange": null,  // 未提及
  "distance": 10000,   // 默认10km
  "location": {
    "lat": 39.9042,
    "lng": 116.4074
  }
}
↓
调用地图API搜索
```

**LLM的职责**：
- 提取关键词：菜系、特色、价格、距离、用餐人数等
- 如果用户未提及某字段，则设为"不限"（API搜索时不过滤）
- 理解模糊表述，如"清淡"→搜索"清淡"、"素食"等关键词
- 处理特殊需求，如"便宜"→认为用户倾向人均<30元的餐厅

**API调用配置**：
- 模型：GPT-4 或 GPT-3.5-turbo
- 温度：0.3（更加确定性）
- 超时时间：10秒

---

#### 2.2.3 地图API搜索模块
**功能描述**：根据LLM输出的条件，调用地图API获取餐厅数据

**优先级策略**：
```
优先级1: OpenStreetMap
  ├─ 使用Overpass API搜索餐厅
  ├─ 返回8家餐厅数据
  └─ 如果返回<8家，降级到优先级2

优先级2: 高德地图 API
  ├─ 调用POI搜索接口
  ├─ 返回8家餐厅数据
  └─ 如果仍<8家，返回"搜索结果为空"提示
```

**搜索参数**：
- 位置：用户当前坐标或手动输入的地址
- 搜索半径：10km（默认）
- 关键词：LLM提取的 `keywords` 字段
- 返回数量：8家

**返回数据结构**：
```json
[
  {
    "id": "unique_id",
    "name": "餐厅名称",
    "cuisineType": "菜系",
    "rating": 4.5,  // 来自高德，OSM可能没有
    "distance": 2.3,  // 单位：km
    "address": "详细地址",
    "phone": "餐厅电话",
    "openingHours": "营业时间",
    "averagePrice": 45,  // 人均价格，来自高德
    "source": "osm" 或 "gaode"  // 数据来源
  }
]
```

**错误处理**：
- API超时（30秒）：显示"网络超时，请重试"
- 搜索结果为空：显示"抱歉，未找到符合条件的餐厅，请修改需求重试"
- API配额用尽（仅高德）：自动回退

---

#### 2.2.4 转盘生成与显示模块
**功能描述**：将搜索到的8家餐厅填充到转盘中

**转盘设计**：
- 形状：圆形分度盘，8个扇形区域
- 每个扇形显示：餐厅名称 + 菜系（仅文字）
- 示例：
  ```
  扇形1: 望京小麥 | 烤肉
  扇形2: 喜茶 | 饮品
  扇形3: 川来川去 | 川菜
  ...
  ```

**转盘的交互**：
1. **初始状态**：8家餐厅均匀分布，转盘静止
2. **用户点击"开始"按钮**：转盘开始旋转
   - 旋转时间：3-5秒
   - 动画：平滑旋转，最后减速停止
   - 指针位置固定在顶部，指向获胜餐厅
3. **转盘停止**：高亮显示指针指向的餐厅
4. **显示推荐结果**：弹出餐厅详情模态框

**补位机制**：
- 用户点击"不想去这家"后，移除该餐厅
- 如果有未显示的餐厅候选项，自动补位到转盘
- 如果没有候选项，该位置留空（显示"暂无"灰色区域）
- 允许用户继续转盘（即使不满8家）
- 用户可以编辑转盘选项，调用地图API搜索餐厅，并填充到转盘，或者删除转盘选项

---

#### 2.2.5 详情展示模块
**功能描述**：显示转盘转出的餐厅完整信息

**展示内容**（模态框或侧边栏）：
```
餐厅名称
菜系 | 人均消费￥XX | 评分★4.5

营业时间：10:00-22:00
地址：北京市朝阳区XXX
电话：010-XXXXXXXX
```

**功能按钮**：
1. **导航**：点击跳转到高德地图/地图App（导航到餐厅）
2. **不想去**：移除此餐厅，转盘补位（如有候选项）或留空
3. **保存**：保存此次转盘记录（需求+结果）
4. **再来一次**：返回转盘继续转（无需重新输入需求）
5. **关闭**：返回转盘主界面

---

#### 2.2.6 历史保存模块
**功能描述**：保存用户的转盘记录（需求+结果），方便回顾

**保存内容**：
```json
{
  "id": "timestamp_uuid",
  "timestamp": "2025-12-13 12:30:00",
  "originalRequest": "最近想吃点清淡的",
  "location": "北京市朝阳区",
  "selectedRestaurant": {
    "name": "望京小麦",
    "cuisineType": "烤肉",
    "address": "...",
    "phone": "..."
  },
  "allRestaurants": [...]  // 完整的8家列表
}
```

**存储位置**：浏览器 localStorage
- Key: `chiShaHistory`
- 最多保存100条记录
- 超过限制时，删除最早的记录

**历史页面功能**：
- 显示所有保存的转盘记录
- 按时间倒序排列
- 每条记录显示：日期、用户需求、选中的餐厅名称
- 点击某条记录可查看详情
- 支持删除单条或清空全部历史

## 三、非功能需求

### 3.1 性能需求
- **页面加载时间**：< 2秒
- **LLM请求响应**：< 10秒
- **地图API搜索**：< 15秒
- **转盘转动时间**：3-5秒

### 3.2 兼容性
- 浏览器：Chrome, Firefox, Safari, Edge (最新两个版本)
- 设备：桌面、平板、手机
- 响应式设计：支持宽度从 320px 到 2560px

### 3.3 可靠性
- API 失败重试机制：最多重试 2 次
- 离线降级：如果网络离线，提示用户并清空输入框
- 错误捕获：所有API调用都有 try-catch，用户看到友好的错误提示

### 3.4 安全性
- 不存储用户的真实位置信息到后端
- API密钥存储在后端环境变量，前端不暴露
- 验证用户输入，防止注入攻击
- localStorage 中仅存储非敏感的转盘记录

## 四、技术架构（参考）

### 4.1 前端技术栈
- 框架：React 或 Vue.js
- 地图展示：Leaflet.js (用于OSM展示)
- UI 组件库：Ant Design 或 Material UI
- 状态管理：Redux / Pinia
- HTTP 客户端：Axios

### 4.2 后端需求（最小化）
- 仅作为 API 代理：
  - 转发 OpenAI API 请求（隐藏密钥）
  - 转发高德地图 API 请求（隐藏密钥）
  - 转发 OpenStreetMap 请求（OSM 可前端直接调用）
- 框架：Node.js + Express 或 Python + Flask

### 4.3 第三方 API
| API | 用途 | 成本 | 限制 |
|-----|------|------|------|
| OpenAI GPT-4/3.5 | 需求理解 | 按token计费 | - |
| OpenStreetMap + Overpass | POI搜索 | 免费 | 社区维护 |
| 高德地图 | POI搜索（备选） | 免费额度50,000次/天 | 超额按量计费 |
| 浏览器 Geolocation | 用户定位 | 免费 | 需要用户授权 |

## 六、数据模型

### 6.1 转盘记录（localStorage）
```typescript
interface TurntableRecord {
  id: string;                    // 唯一标识
  timestamp: number;             // 时间戳
  originalRequest: string;       // 用户原始需求
  location: {
    address: string;             // 手动输入的地址或坐标
    lat: number;
    lng: number;
  };
  selectedRestaurant: {
    id: string;
    name: string;
    cuisineType: string;
    rating?: number;
    distance: number;
    address: string;
    phone: string;
    openingHours?: string;
    averagePrice?: number;
    source: 'osm' | 'gaode';
  };
  allRestaurants: Restaurant[];  // 完整的8家列表（便于重新查看）
}

interface Restaurant {
  id: string;
  name: string;
  cuisineType: string;
  rating?: number;
  distance: number;
  address: string;
  phone: string;
  openingHours?: string;
  averagePrice?: number;
  source: 'osm' | 'gaode';
}
```
